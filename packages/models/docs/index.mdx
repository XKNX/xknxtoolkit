`xknx-models` is the foundation layer of the xknx toolkit. It provides fully typed Python classes for all KNX project XML formats, plus helpers for loading, detecting, and serializing those documents.

## Supported versions

Schema versions **10, 11, 12, 13, 14, 20, 21, 22, and 23** are all supported. Each version is available as its own sub-module (`v10` through `v23`), giving you static type coverage regardless of which ETS export you're working with.

## Installation

```bash
pip install xknx-models
```

## Usage

```python
from xknxmono.models import load_xml, serialize_xml, detect_version

# Auto-detect version and parse
knx = load_xml(xml_bytes)

# Explicit version
knx = load_xml(xml_bytes, version="20")

# Round-trip back to XML
xml_out = serialize_xml(knx, version="20")

# Inspect version without parsing
version = detect_version(xml_bytes)  # e.g. "20"
```

`load_xml` returns the `Knx` dataclass for whichever version it parsed (`v10.Knx`, `v20.Knx`, ...) — its shape follows that version's schema exactly.

## Intermediate representation

Writing logic against nine separate schema versions means either re-implementing it nine times or hand-rolling your own unification. `xknxmono.models.intermediate` is that unification, done once: a single, version-agnostic set of dataclasses that every version's model converts into, so the rest of your code only has to know one shape.

```python
from xknxmono.models import load_xml
from xknxmono.models.adapters.convert import Context, convert
from xknxmono.models.intermediate.knx import Knx

version = "20"
model = load_xml(xml_bytes, version)  # version-specific model (v20.Knx)
knx = convert(Context(version=version), model, Knx)  # unified IR
```

`convert()` isn't limited to the root `Knx` object — pass any version-specific dataclass instance together with its `intermediate` counterpart to convert just that subtree.

## API reference

| Symbol                          | Description                                                       |
| -------------------------------- | ------------------------------------------------------------------ |
| `load_xml(source, version?)`     | Parse XML bytes into a version-specific `Knx` object              |
| `serialize_xml(obj, version)`    | Serialize a version-specific `Knx` object back to XML bytes       |
| `detect_version(xml_bytes)`      | Extract the schema version from the XML namespace declaration     |
| `get_model_class(version)`       | Return the version-specific `Knx` dataclass for a version string  |
| `SUPPORTED_VERSIONS`             | Frozenset of all supported version strings                        |
| `VersionError`                   | Raised when a version cannot be detected or is unsupported        |
| `adapters.convert.convert(ctx, src, target_cls)` | Convert a version-specific dataclass instance into its `intermediate` equivalent |
| `adapters.convert.Context(version)` | Per-conversion state: source version, PUID allocation, logging |

Version sub-modules (`v10`–`v14`, `v20`–`v23`) are re-exported from the package root and contain the full generated class hierarchy for that schema version — they're what `load_xml` parses into, not something you're expected to build logic against directly. Convert to `intermediate` for that.
